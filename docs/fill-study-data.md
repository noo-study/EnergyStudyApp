# 빈칸 학습 데이터 등록 형식

데이터는 `index.html`의 `id="fill-study-data"`인 독립된 JSON 영역에 있습니다. 화면 로직은 `app.js`에 있습니다. GitHub Pages 워크플로를 변경하지 않고 배포할 수 있도록 현재는 JSON을 HTML 안에 보관하며, 빈칸 학습과 전체 서술형이 동일한 데이터를 읽습니다. 실제 원문은 한 번만 저장합니다.

## 원문 분리 형식 (신규 자료 권장)

| 필드 | 의미 |
| --- | --- |
| `id` | 변경하지 않는 용어 ID. 자료 개정·메뉴 이동 때 기존 ID를 다른 문제에 재사용하지 않음 |
| `term` | 용어명 |
| `definition` | 인용부호, 수치, 단위, 괄호, 단서를 포함한 정의 원문 전체 |
| `blanks` | 빈칸 후보 객체 배열 |
| `blankSets` | 위치 변경 모드에서 선택할 후보 ID 배열들의 배열 |
| `source.law` | 법령명 |
| `source.noticeNumber` | 고시번호 |
| `source.effectiveDate` | 시행일 (`YYYY-MM-DD`) |
| `source.article` | 조문 위치 |
| `source.pdfPages` | 개발용 원문 PDF의 페이지 번호 배열 |

`blanks` 객체는 `id`, `start`, `end`, `answer`, `core`, `acceptedAnswers`를 가집니다. `start`는 포함, `end`는 미포함인 JavaScript 문자열 위치(UTF-16 기준)입니다. `definition.slice(start, end)`가 `answer`와 정확히 일치해야 하며, 후보끼리 겹치면 안 됩니다. `core`와 `acceptedAnswers`는 아래 기존 형식과 같은 의미입니다.

앱은 이 위치 정보로 화면용 `definitionParts`를 메모리에서만 만듭니다. 원문은 자르거나 덮어쓰지 않으며, 원문 공개 화면은 저장된 `definition`을 그대로 사용합니다. 잘못된 위치나 정답이 등록되면 자료 오류로 처리합니다. 기존 `definitionParts` 형식도 지원하므로 기존 문제 ID와 복습 기록을 마이그레이션하거나 지울 필요가 없습니다.

| 고유 ID | 용어 | 위치 | PDF 페이지 |

| `energy-saving-design-art5-10-cha` | 외단열 | 차목 | 4 |
| `energy-saving-design-art5-10-ka` | 방습층 | 카목 | 4~5 |
| `energy-saving-design-art5-10-ta` | 평균 열관류율 | 타목 | 5 |

PDF 4~5쪽을 이미지로 확인하고 전체 정의를 대조했습니다. PDF의 페이지 머리말·꼬리말과 조판 줄바꿈만 제거해 자연스러운 문장으로 연결했습니다. 원문 대조 테스트는 공백을 제외한 모든 문자(수치·단위·괄호·문장부호 포함)를 비교합니다. 추가 동의어는 등록하지 않았으며 모든 `acceptedAnswers`는 빈 배열입니다. 빈칸 후보와 조합은 원문에 실제 존재하는 구절만 지정했습니다.

PDF는 `.gitignore`의 `/references/`로 Git 추적에서 제외됩니다. 기존 배포 워크플로는 정해진 앱 파일만 복사하므로 PDF와 `tests`, `docs`는 웹 배포 대상이 아닙니다.

검증 명령:

```text
node tests/fill-study.test.cjs
python tests/verify-pdf-source.py
```

PDF 대조 테스트에는 로컬 원본 PDF와 개발용 Python `pypdf`가 필요합니다. 웹앱 실행에는 Python이나 외부 라이브러리가 필요하지 않습니다.

## 기존 조각 형식 (호환 유지)

검증된 자료가 준비되면 배열에 다음 필드를 가진 객체를 등록합니다.

| 필드 | 의미 |
| --- | --- |
| `id` | 용어의 고유한 문자열 ID |
| `term` | 용어명 |
| `definitionParts` | 정의 원문을 순서대로 나눈 배열. 일반 부분은 문자열, 빈칸 후보는 아래 객체로 작성 |
| `blankSets` | 위치 변경 모드에서 사용할 후보 ID 배열들의 배열. 모든 조합은 직접 검증하여 등록 |
| `source.law` | 법령명 |
| `source.article` | 조항 |

빈칸 후보 객체의 필드:

| 필드 | 의미 |
| --- | --- |
| `id` | 같은 정의 안에서 고유한 후보 ID |
| `text` | 정의 원문에 있는 정확한 단어 또는 구절. 항상 정답으로 인정 |
| `core` | 핵심 고정 빈칸이면 `true`, 그 외에는 `false` |
| `acceptedAnswers` | 사전에 검증한 추가 허용 정답 문자열 배열. 추가 답이 없으면 `[]` |

`definitionParts`의 문자열과 후보 `text`를 순서대로 이어 붙인 결과가 정확한 정의 원문이어야 합니다. 공백·문장부호도 원문대로 보존합니다. 고정 모드는 `core: true`인 후보를 전부 가립니다. 위치 변경 모드는 `blankSets`에 등록한 조합 중 하나만 선택하며, 같은 조합이 다시 선택될 수도 있습니다.

채점에서는 유니코드 NFC 정규화와 공백 제거만 합니다. 대소문자·문장부호·오탈자를 임의로 보정하지 않습니다. 동의어는 `acceptedAnswers`에 명시된 것만 인정합니다. 실제 법령을 자동 생성하거나 검색하여 추가하지 않습니다.

외부 JSON으로 분리할 때는 같은 배열을 JSON 파일에 저장하고 데이터 영역에 `data-src="./data/terms.json"`처럼 상대 경로를 추가합니다. 앱은 해당 파일을 읽고 동일한 형식을 검사합니다. 이 경우 **해당 JSON 파일이 GitHub Pages 배포 대상에 포함되도록 별도 배포 설정도 필요**합니다. 이번 작업에서는 배포 설정을 변경하지 않았습니다.

외부 JSON 요청에 실패하거나 형식이 잘못되면 오류 안내와 재시도 버튼을 표시합니다. 빈 배열은 ‘등록된 학습자료가 없습니다’로 표시합니다. 입력값·채점 결과는 화면 메모리에만 보관합니다.

## 수동 복습 등록

사용자가 ‘다시 볼 문제’를 누를 때만 localStorage의 전용 키 `bea.fillStudy.statuses.v1`에 기록합니다. 값은 `{ "id": "용어의 고유 ID", "status": "review" }` 형태의 객체 배열이며, ID와 상태 이외에는 저장하지 않습니다. 같은 ID는 한 번만 저장합니다. 용어 ID는 자료를 수정해도 유지하고 다른 용어에 재사용하지 않아야 합니다.

`review`는 복습 중, `completed`는 학습 완료입니다. 이번에는 `review` 등록만 제공하며, 이미 저장된 `completed`는 그대로 보존합니다. 등록된 항목은 ‘복습 등록됨’으로 표시하고 중복 등록 버튼을 비활성화합니다. 완료 보관함과 복습 목록 화면은 아직 없습니다.

빈칸 모드나 정오 여부는 등록에 영향을 주지 않습니다. 저장소 읽기·쓰기 또는 데이터 형식 오류가 발생하면 안내를 표시하고 현재 학습은 계속할 수 있습니다. 잘못된 기존 값을 자동으로 덮어쓰거나 지우지 않으며, 다른 localStorage 키와 IndexedDB도 건드리지 않습니다. JSON 백업·복원 기능은 아직 구현하지 않았습니다.

localStorage는 기기·브라우저·웹사이트 주소별 저장소입니다. Safari와 홈 화면 앱의 저장소는 다를 수 있으며, 앱이 브라우저의 데이터 삭제를 막거나 다른 기기로 동기화하지는 않습니다.
