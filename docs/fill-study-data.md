# 빈칸 학습 데이터 등록 형식

현재 실제 데이터는 없습니다. `index.html`의 `id="fill-study-data"`인 JSON 영역은 빈 배열 `[]`입니다. 화면 로직은 `app.js`에 있으며 데이터와 별도로 관리합니다.

검증된 자료가 준비되면 배열에 다음 필드를 가진 객체를 등록합니다.

| 필드 | 의미 |
| --- | --- |
| `id` | 용어의 고유한 문자열 ID |
| `term` | 용어명 |
| `definitionParts` | 정의 원문을 순서대로 나눈 배열. 일반 부분은 문자열, 빈칸 후보는 아래 객체로 작성 |
| `blankSets` | 위치 변경 모드에서 사용할 후보 ID 배열들의 배열. 모든 조합은 직접 검증하여 등록 |
| `source.law` | 법령명 |
| `source.article` | 조항 |

빈칸 후보 객체의 필드:

| 필드 | 의미 |
| --- | --- |
| `id` | 같은 정의 안에서 고유한 후보 ID |
| `text` | 정의 원문에 있는 정확한 단어 또는 구절. 항상 정답으로 인정 |
| `core` | 핵심 고정 빈칸이면 `true`, 그 외에는 `false` |
| `acceptedAnswers` | 사전에 검증한 추가 허용 정답 문자열 배열. 추가 답이 없으면 `[]` |

`definitionParts`의 문자열과 후보 `text`를 순서대로 이어 붙인 결과가 정확한 정의 원문이어야 합니다. 공백·문장부호도 원문대로 보존합니다. 고정 모드는 `core: true`인 후보를 전부 가립니다. 위치 변경 모드는 `blankSets`에 등록한 조합 중 하나만 선택하며, 같은 조합이 다시 선택될 수도 있습니다.

채점에서는 유니코드 NFC 정규화와 공백 제거만 합니다. 대소문자·문장부호·오탈자를 임의로 보정하지 않습니다. 동의어는 `acceptedAnswers`에 명시된 것만 인정합니다. 실제 법령을 자동 생성하거나 검색하여 추가하지 않습니다.

외부 JSON으로 분리할 때는 같은 배열을 JSON 파일에 저장하고 데이터 영역에 `data-src="./data/terms.json"`처럼 상대 경로를 추가합니다. 앱은 해당 파일을 읽고 동일한 형식을 검사합니다. 이 경우 **해당 JSON 파일이 GitHub Pages 배포 대상에 포함되도록 별도 배포 설정도 필요**합니다. 이번 작업에서는 배포 설정을 변경하지 않았습니다.

외부 JSON 요청에 실패하거나 형식이 잘못되면 오류 안내와 재시도 버튼을 표시합니다. 빈 배열은 ‘등록된 학습자료가 없습니다’로 표시합니다. 진행 상태·입력값은 현재 화면 메모리에만 보관하며 저장 데이터를 읽거나 삭제하지 않습니다.
